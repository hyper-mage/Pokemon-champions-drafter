<!-- VERIFIED export facts, from CLAUDE.md section Export Formats. Empirically checked
     against pokemon-showdown 0.11.11's Teams.import(). -->

  "Venusaur\n\nGarchomp\n\nRotom-Wash\n"   ->  3 mons.  CORRECT.
  "Venusaur\nGarchomp\nRotom-Wash\n"        ->  1 mon.   SILENTLY DROPS THE REST.
  "Venusaur\n\nTauros-Paldea-Aqua\n"        ->  2 mons.  hyphenated formes parse fine.

The blank line is the record separator. Emitting newline-separated names is the single
most likely export bug in the project. Cover it with a test.

<!-- Showdown's first-line parser, read directly from sim/teams.ts::parseExportedTeamLine.
     Three special forms a naive exporter can collide with: -->
  `X @ Y`                       -> Y is parsed as the item
  line ending in ` (M)` / ` (F)` -> parsed as GENDER, and the suffix is stripped
  line ending in `)` containing `(` -> parsed as `Nickname (Species)`

Therefore: never emit a parenthesised suffix. `Nidoran (M)` yields species "Nidoran",
which does not exist. The correct names are `Nidoran-M` and `Nidoran-F`, emitted verbatim.

<!-- Why a bare Mega forme is invalid, from sim/team-validator.ts -->
A Mega forme's species record has a truthy `battleOnly` and a `requiredItem`. Exporting
`Venusaur-Mega` imports fine and then refuses to battle with
`Venusaur-Mega transforms in-battle with Venusaurite, please fix its item.`
The only form that validates is the BASE species plus the stone: `Venusaur @ Venusaurite`.
Charizard's stones are `Charizardite X` and `Charizardite Y`.

<!-- pokebase.app, investigated but not hand-tested -->
Entry point button label: `New/Import Team`
Import textarea id `team-import-paste`, aria-label `Team paste to import`
Its server action is `parseShowdownTeamPaste`, and its own placeholder is a standard
Showdown paste. Its help link points at Showdown's TEAMS.md. So it should accept the same
text — that inference is exactly what this plan's spike tests.

<!-- Phase 1 scope note -->
Phase 1 has no Mega rounds and no X-versus-Y selection (DRFT-15 is Phase 2), so no slot
this phase produces is ever Mega-typed. The function must nonetheless SUPPORT Mega slots,
proven by fixture tests and by the spike's hand-built team. Building it now is what stops
the export format being reopened in Phase 3.

    where `slots` is an array of `{ monId, megaStone } | null` and `rosterById` is a lookup
    from roster id to RosterEntry. It returns a string.

    Rules, all of which are test-covered:
      - Drop null slots.
      - For each remaining slot, look the entry up by `monId` and take its `name` field

      - Join every line with `\n\n` and append a single trailing `\n`.
      - Never wrap anything in parentheses and never append a ` (M)` or ` (F)` suffix.
