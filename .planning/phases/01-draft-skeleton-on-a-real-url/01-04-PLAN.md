  <action>
    Write `scripts/build-sprites.mjs`, a Node ESM script with no new dependencies.

    Step 1 — build the slug-to-id map. Fetch
    `https://pokeapi.co/api/v2/pokemon?limit=100000&offset=0` once and build a
    `Map<slug, number>` from `results[].name` to the trailing id in `results[].url`.
    Cache the raw response under `scripts/.cache/pokeapi-index.json` (gitignored) so
    re-runs are offline and fast.

    Step 2 — derive a candidate PokeAPI slug for each sprite target. Targets are every
    draftable roster entry PLUS every entry in every `megaFormes` array. Derive the slug
    from the Showdown `name` field by lowercasing, replacing every run of characters
    outside `[a-z0-9]` with a single hyphen, and trimming hyphens. Worked examples that
    must come out right: `Rotom-Wash` to `rotom-wash`, `Tauros-Paldea-Combat` to
    `tauros-paldea-combat`, `Charizard-Mega-X` to `charizard-mega-x`, `Mr. Rime` to
    `mr-rime`, `Ho-Oh` to `ho-oh`, `Type: Null` to `type-null`, `Porygon-Z` to `porygon-z`,
    `Nidoran-M` to `nidoran-m`, `Kommo-o` to `kommo-o`, `Farfetch’d` to `farfetchd`,
    `Flabébé` to `flabebe`. Note that the U+2019 and the accented characters must be
    stripped, not hyphenated — apply `String.prototype.normalize('NFD')` and drop combining
    marks before the character-class replacement, then collapse hyphens.

    Step 3 — apply `scripts/pokeapi-slug-overrides.json`, a hand-maintained
    `{ "<rosterEntryId>": "<pokeapiSlug>" }` map consulted before the derivation. Start it
    empty. Any target whose derived slug is not in the PokeAPI map gets printed as
    `UNRESOLVED <rosterId> derived=<slug>` at the end of the run; add those to the override
    file and re-run until the unresolved list is empty or every remaining entry is
    genuinely absent from PokeAPI.

    Step 4 — download. For each resolved id, GET
    `https://raw.githubusercontent.com/PokeAPI/sprites/master/sprites/pokemon/{id}.png`
    with a small concurrency limit (8 in flight is plenty; do not hammer). Write to
    `public/sprites/{id}.png`. Skip the download if the file already exists and is a valid
    PNG, so re-runs are cheap.

    Validate every downloaded byte stream before writing: the first 8 bytes must be the PNG
    magic `89 50 4E 47 0D 0A 1A 0A`. Anything else is a 404 page or a redirect, not art —
    treat it as a miss, not a file.

    Step 5 — measure. Read width and height straight out of the PNG IHDR chunk: bytes 16-19
    are the big-endian width, bytes 20-23 the height. No image library, ten lines of
    Buffer reads. Record the dimensions of every sprite. If they are not all identical,
    record the modal size as `nativeWidth`/`nativeHeight` and list every outlier in the
    summary — the pool grid renders at one size and outliers need to be known.

    Step 6 — write results:
      - `public/data/sprite-meta.json`: `{ generatedAt, nativeWidth, nativeHeight,
        outliers: [{ rosterId, width, height }], resolved: <n>, missing: [<rosterId>...],
        byRosterId: { "<rosterId>": { pokeapiId, file } } }`, with a DO NOT EDIT header
        field.
      - Write back into `public/data/roster.mb.json` and `public/data/roster.ma.json`:
        set `spriteId` to the PokeAPI numeric id and `spriteMissing` to `false` on hits;
        set `spriteId` to `null` and `spriteMissing` to `true` on misses (D-05). Do the
        same for each object inside `megaFormes`. Preserve the existing key order and the
        entry sort so the diff stays readable, and recompute nothing else — in particular
        do NOT recompute `checksum`, since `checksum` covers the entries array and sprite
        fields are part of it; instead recompute the checksum with the same canonical-JSON
        routine `build-roster.mjs` uses, and state in the script header that sprite
        resolution is part of snapshot generation.
      - Print the D-05 summary: `<n> of <total> targets have no sprite: <ids>`, then exit 0.
        A 404 must never fail this build.

    Add `npm run build:sprites` and a `build:data` script that runs
    `build:roster mb && build:roster ma && build:sprites` in order.

    Add `scripts/.cache/` to .gitignore. `public/sprites/` is NOT ignored — the whole point
    is that the art is committed.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PokeAPI / raw.githubusercontent.com → repository | Roughly 310 binary files fetched from third-party hosts and committed permanently |
| committed sprite bytes → every visitor's browser | Whatever is committed here is served from the project's own origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-20 | Tampering | downloaded sprite bytes | mitigate | Every response is validated against the PNG magic `89504e470d0a1a0a` before being written; a 404 HTML page or a redirect body is recorded as a miss rather than committed as a `.png` |
| T-01-21 | Tampering | build script fetching an attacker-controlled URL | mitigate | Both hosts are hardcoded constants in the script; the PokeAPI id map supplies only integers, which are substituted into a fixed path template — no attacker-controlled path segment is possible |
| T-01-22 | Denial of Service | roughly 1 MB and 310 requests on the visitor's first load | accept | Explicitly chosen in D-16. Precached once by the service worker in plan 11, after which the app is fully offline |
| T-01-23 | Repudiation | shipping art without licence clearance | mitigate | Task 2 is a hard gate: if `LICENCE.txt` does not permit redistribution the art is not committed and the blocker is reported |
| T-01-24 | Information Disclosure | broken-image glyphs reading as a broken app | mitigate | D-05 records `spriteMissing` at build time so the runtime never fires a request it knows will 404; the D-04 placeholder renders instead |
</threat_model>
