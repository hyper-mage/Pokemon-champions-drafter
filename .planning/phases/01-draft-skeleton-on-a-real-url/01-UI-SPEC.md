# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** the five surfaces Phase 1 renders — pool grid, draft board, undo, storage/persistence warnings, export panel. This phase establishes the token system every later phase inherits. It is a contract, not a style showcase.

**Binding upstream:** `CLAUDE.md` (locked stack), `.planning/phases/01-draft-skeleton-on-a-real-url/01-CONTEXT.md` (D-01…D-18), `.planning/REQUIREMENTS.md` (ROST-01…12, SHEL-01…07, PERS-01…07, EXPO-01…06).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-built Preact components under `src/ui/components/` |
| Icon library | none — no icon font, no icon package. Any unavoidable glyph is an inline SVG committed under `src/ui/icons/`. Phase 1 needs zero icons. |
| Font | System stack, no webfont (see Typography). Zero network requests, satisfies SHEL-03 offline and D-01 zero-cost, no FOUT. |

**Hard constraint — do not violate.** `CLAUDE.md` locks the project to exactly two runtime dependencies (`preact`, `@preact/signals`). No CSS framework, no Tailwind, no CSS-in-JS runtime, no component registry, no icon package may be added in this phase or any later one. Styling is plain CSS driven by custom properties, per D-07.

**Styling mechanism (D-07):** a single `src/ui/tokens.css` declaring every token below on `:root`, imported once. Component CSS files consume tokens only — no raw hex, no raw px for anything the token table covers. This is what makes Phase 2's three density settings (DRFT-06) and across-the-room legibility (DRFT-14) a token swap rather than a restyle.

Set `color-scheme: dark` on `:root` so native scrollbars, form controls, and the file picker match the theme.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Sprite-to-name gap inside a pool cell, inline label padding |
| `--space-2` | 8px | Pool grid gutter, board cell gutter, button icon/text gap |
| `--space-3` | 16px | Default element spacing, button padding-x, card padding |
| `--space-4` | 24px | Page padding, panel padding, gap between board and pool |
| `--space-5` | 32px | Gap between top bar, turn banner, and board |
| `--space-6` | 48px | Gap between major screen sections (board block ↔ pool block) |
| `--space-7` | 64px | Blocking-screen vertical padding, completed-draft section breaks |

Exceptions: **none.** Every value is a multiple of 4.

### Size tokens (not spacing — sizing constraints)

These are separate from the spacing scale but are still multiples of 4. They exist as tokens specifically so Phase 2's density toggle swaps them.

| Token | Value | Notes |
|-------|-------|-------|
| `--sprite-lg` | 96px | Pool cell sprite. **Measured, not assumed.** `scripts/build-sprites.mjs` read the IHDR chunk of all 311 committed PokeAPI PNGs on **2026-08-04**: every file is **96×96, zero outliers** (`public/data/sprite-meta.json` → `nativeWidth` / `nativeHeight`, `dimensionHistogram: { "96x96": 311 }`). The cell therefore renders 1:1 with no scaling blur. `_placeholder.png` is generated at the same 96×96 so a gap cannot break grid rhythm. Plan 01-05 wires the pool `<img>` `width`/`height` attributes to this same measured figure. |
| `--sprite-sm` | 48px | Board / team-strip chip sprite. Exact 2:1 integer downscale of the **measured** 96px source, so it stays crisp. |
| `--cell-min` | 112px | Pool grid `minmax()` floor |
| `--cell-h` | 144px | Pool cell height |
| `--target-min` | 44px | Minimum interactive target, width and height. Exceeds WCAG 2.2 SC 2.5.8 (24px) and meets SC 2.5.5 (44px). |
| `--radius` | 8px | All corners. One radius, no variants. |
| `--border-w` | 2px | State-carrying borders (selected, on-the-clock, focus-adjacent) |
| `--hairline-w` | 1px | Decorative dividers only |

**Phase 2 density swap contract:** the three densities (DRFT-06) change exactly four tokens — `--sprite-lg`, `--cell-min`, `--cell-h`, `--text-label`. Nothing else. Build Phase 1 so that is true.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 18px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 24px | 600 | 1.25 |
| Display | 36px | 600 | 1.15 |

Exactly 4 sizes, exactly 2 weights (400 regular, 600 semibold). No 500, no 700, no italics.

These four are the complete set. **No surface may introduce a fifth size** — including the monospace export block, which renders at `--text-body`. Every size in the Surface Contracts below cites one of these four tokens by name; a raw `px` font-size anywhere in the CSS is a contract violation.

| Token | Applies to |
|-------|-----------|
| `--text-body` (18/400/1.5) | Paragraph copy, warning bodies, banner text, button labels, the export paste `<pre>` block |
| `--text-label` (14/600/1.4) | Pool cell species names, board chip names, round headers, helper text, muted meta |
| `--text-heading` (24/600/1.25) | Panel and player headings, dialog headings |
| `--text-display` (36/600/1.15) | The on-the-clock turn banner, the one `<h1>` per screen |

Body is 18px rather than the usual 16px on purpose: this is a shared screen read by a room, and D-07 commits to large-target now so DRFT-14 is a token swap later.

**Font stacks:**

```css
--font-sans: ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto,
             "Helvetica Neue", Arial, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas,
             "Liberation Mono", monospace;
```

`--font-mono` is a **family token only — it carries no size, weight, or line-height of its own** and does not add a row to the scale above. It has a **single scoped role**: the export paste block (`<pre>`), which sets `font-family: var(--font-mono)` and takes its size from `--text-body` like any other body-copy surface. Mono is required there because EXPO-03's blank-line separation is the single most likely export bug (`CLAUDE.md`: newline-separated species silently imports only the first Pokémon), and monospace makes the exact emitted text verifiable by eye. Mono is used nowhere else.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0F1216` | Page background, blocking-screen backdrop |
| Secondary (30%) | `#1A1F26` | Pool cells, board cells, panels, banners, top bar, `<pre>` blocks |
| Accent (10%) | `#FFCB05` | See reserved-for list below — nothing else |
| Destructive | `#FF7A70` | See reserved-for list below — nothing else |

### Full token table

| Token | Value | Contrast | Role |
|-------|-------|----------|------|
| `--color-bg` | `#0F1216` | — | Dominant surface |
| `--color-surface` | `#1A1F26` | — | Secondary surface (cells, panels, banners) |
| `--color-surface-raised` | `#232A33` | — | Hover state of an interactive secondary surface |
| `--color-text` | `#E8EDF2` | 15.8:1 on bg, 13.9:1 on surface | Primary text |
| `--color-text-muted` | `#9AA7B4` | 7.6:1 on bg, 6.8:1 on surface | Helper text, round labels, meta. Passes AAA. |
| `--color-hairline` | `#313A45` | decorative | 1px dividers only — never carries state |
| `--color-border-strong` | `#66768A` | 3.6:1 on surface, 4.1:1 on bg | Every border that carries meaning (empty board slot, pool cell edge, secondary button outline) |
| `--color-accent` | `#FFCB05` | 12.3:1 on bg, 10.9:1 on surface | Accent — reserved list below |
| `--color-accent-ink` | `#0F1216` | 12.3:1 on accent | Text/glyph on an accent fill |
| `--color-accent-soft` | `rgba(255,203,5,0.12)` | decorative tint | On-the-clock cell tint. Decorative only — the 2px accent border and the banner text carry the actual signal. |
| `--color-danger` | `#FF7A70` | 7.4:1 on bg, 6.5:1 on surface | Destructive/data-loss — reserved list below |
| `--color-danger-ink` | `#0F1216` | 7.4:1 on danger | Text on a danger fill |
| `--focus-ring` | `var(--color-accent)` | ≥8.8:1 on any surface | Keyboard focus outline |

All ratios computed against the WCAG 2.x relative-luminance formula. Every text pairing above clears 4.5:1; every state-carrying non-text boundary clears 3:1.

### Accent reserved for

Exactly three things. Never "all interactive elements."

1. **The on-the-clock indicator** — the turn banner's 4px left rule and the active player's name inside it, plus the `--border-w` border and `--color-accent-soft` tint on the single board cell that is about to be filled.
2. **The primary action of the current screen** — accent fill with `--color-accent-ink` text. One per screen; on the completed-draft screen it repeats once per player panel because it is the same action, not a second one. Phase 1's primary actions: `Continue without saving`, `Take over drafting here`, `Download tournament JSON`, `Copy team paste`.
3. **The keyboard focus ring** — `outline: 3px solid var(--focus-ring); outline-offset: 2px;`. The 2px offset places the ring on the background, so it stays visible even around an accent-filled button.

The draft screen deliberately has **no accent-filled button at all**. Picking is the action, and the pool cells are the target. Undo, Download JSON, and Import JSON are all secondary (transparent fill, `--color-border-strong` outline, `--color-text` label).

### Destructive reserved for

Exactly two things in Phase 1.

1. **The storage-unavailable blocking screen** (PERS-02 / D-13) — heading colour and the 4px left rule. This is a genuine data-loss warning, not decoration.
2. **The import-overwrite confirmation's confirm button** (PERS-05) — danger fill with `--color-danger-ink`. This is the only destructive action in the phase.

**Undo is never destructive-coloured.** D-08's one-click no-confirm pick is only defensible because D-10's unlimited undo ships with it, so undo must read as routine and reversible: secondary button styling, plain label, no red, no warning icon, no confirmation.

### Colour is never the only signal

| State | Colour signal | Non-colour signal |
|-------|--------------|-------------------|
| On the clock | accent border + tint | the `--text-display` banner naming the player and round |
| Disabled | `opacity: 0.45` | native `disabled` + `aria-disabled="true"` |
| Read-only tab | none | `inert` on the draft region + a text banner |
| Missing sprite | none | the committed placeholder image; the species name is unchanged |
| Empty board slot | `--color-border-strong` | `1px dashed` border style vs solid for filled |

|---------|------|
| Primary CTA | `Copy team paste` |

**Copy rules for this phase:**
- Second person, present tense, no exclamation marks, no emoji.
- Errors state the problem *and* the next action. Never a bare "Something went wrong".
- Never blame the user; the storage warning blames the browser, which is accurate.
- The export helper text **names no third-party menu path on purpose.** It previously read `Paste into Pokémon Showdown → Teambuilder → import, or pokebase.app → New/Import Team.` Neither arrow-path was ever read off a running site: the Showdown half was a guess, and while `New/Import Team` and `Team paste to import` are real strings recovered from pokebase's shipped JS (`CLAUDE.md` §Export Formats), static analysis of a bundle is not an observation of the live UI, and both sites are free to relabel a button without telling us. The export spike (plan 01-08) settled the paste *format* against both targets but never captured the menu wording — see `docs/export-verification.md`, where those two rows remain PENDING. Rather than leave unverified third-party wording sitting in an approved contract, the string describes the destination generically. Every site involved has a team import field; only the route to it is uncertain. If someone later reads the real labels off both running UIs, this row may be made specific again.

## Surface Contracts

The five surfaces this phase renders. The planner turns these into tasks; the executor treats them as the visual source of truth.

### Component inventory (D-06 — real components, thinly wired)

| Component | Phase 1 wiring | Phase 2 adds |
|-----------|---------------|--------------|
| `PoolGrid` | render, click-to-pick, remove-on-pick | search (DRFT-08), type/Mega filters (DRFT-09), density (DRFT-06) |
| `MonCard` | sprite + name | typing + base stats (DRFT-05) |
| `MonChip` | 48px sprite + name, used inside `TeamStrip` | — |
| `TeamStrip` | one player's six slots as a board row | typed slots (Phase 3) |
| `BoardGrid` | round header + N `TeamStrip`s | scales to 8 players unchanged |
| `TurnBanner` | round, active player, live region | up-next preview |
| `TopBar` | Undo, Download JSON, Import JSON… | density toggle, search |
| `Dialog` | storage warning, import confirm | DRFT-13 confirmations |
| `ExportPanel` | copy button + `<pre>` paste | — |

**Note on D-06:** the "team strip" and the "board grid" are *not* two renderings of the same data. `TeamStrip` renders one player's six slots; `BoardGrid` stacks N `TeamStrip`s under a shared round header. Both components survive into Phase 2, and Phase 1 renders each exactly once. Do not build a separate duplicate team panel in this phase — the board row *is* the live roster (DRFT-11 in spirit; typed-slot team panels arrive with the Phase 3 compiler).

### 1. Pool grid

```css
grid-template-columns: repeat(auto-fill, minmax(var(--cell-min), 1fr));
gap: var(--space-2);
```

- Each cell is a real `<button type="button">`, `--cell-h` tall, `--color-surface` fill, `--hairline-w solid var(--color-border-strong)` border, `--radius` corners. Whole cell is the target; far above `--target-min`.
- Cell content, top to bottom: `<img>` at `--sprite-lg`, `--space-1` gap, species name at `--text-label`, centred, `text-overflow: ellipsis` on one line with the full name in `title`.
- `<img>` **must** carry explicit `width`/`height` attributes and `alt=""` (decorative — the adjacent name is the accessible label). The explicit dimensions prevent 234 simultaneous layout shifts. The attributes carry the sprite's measured native size — `96`/`96`, confirmed against all 311 committed PNGs on 2026-08-04 (see the Size tokens table) — read from `public/data/sprite-meta.json` rather than typed as a literal, so the attributes and `--sprite-lg` cannot drift apart. `loading="lazy"` is **not** used: D-16 precaches every sprite, so lazy loading buys nothing and costs pop-in.
- Missing sprite (ROST-11 / D-04 / D-05): render the single committed placeholder authored at exactly the same pixel dimensions as the real sprites, chosen by the `spriteMissing: true` flag on the roster entry. **Never** fire a request the build already knows 404s. The species name renders unchanged.
- Hover: fill → `--color-surface-raised`, 120ms ease. Focus: the accent ring. Active: no separate style needed.
- **A picked species is removed from the DOM immediately** — not greyed, not disabled. This is the success criterion's literal wording.
- Above the grid: `Pool` at `--text-heading` and `{n} available` at `--text-label` in `--color-text-muted`.
- **Performance:** ship without virtualization — 234 cells is unremarkable and `CLAUDE.md` explicitly rejects virtualization libraries. If profiling shows pool render exceeding 16ms, the one sanctioned escape hatch is exactly `content-visibility: auto; contain-intrinsic-size: var(--cell-min) var(--cell-h);` on `.pool-cell`. Nothing else.

### 2. Draft board

**Orientation: players as rows, rounds as columns.**

```css
grid-template-columns: 160px repeat(6, minmax(0, 1fr));
gap: var(--space-2);
```

Rationale, because this decision must survive to 8 players: rows grow downward for free as player count rises (2 → 8 in Phase 2), a player's team reads as one continuous horizontal line so `TeamStrip` and the board row are the same element rather than duplicated state, and it matches the Google Sheets draft board this audience already uses (`.planning/research/FEATURES.md`).

- Row label column (160px): player name at `--text-heading`.
- Round headers `R1`…`R6` at `--text-label`, `--color-text-muted`.
- Filled cell: `MonChip` — `--sprite-sm` sprite + name at `--text-label`, `--color-surface` fill.
- Empty future slot: `--hairline-w dashed var(--color-border-strong)`, transparent fill, no text.
- **The next slot to be filled**: `--border-w solid var(--color-accent)` + `--color-accent-soft` fill. Exactly one such cell exists at any time.
- Board cells are **not** interactive in Phase 1. Undo is a top-bar button, not a per-cell control.
- Below 720px viewport: the board scrolls horizontally and the 160px label column takes `position: sticky; left: 0` with a `--color-bg` backdrop. Same mechanism carries 8 players later.
- Pre-first-pick empty state: the board renders with all 12 dashed slots, plus the empty-state heading and body from the copywriting contract in the board region.

### 3. Undo (SHEL-06 / D-10)

- Lives in the sticky `TopBar`, always reachable without scrolling. Label `Undo last pick`.
- Secondary styling: transparent fill, `--hairline-w solid var(--color-border-strong)`, `--color-text` label, `--text-body`, `--space-3` padding-x, at least `--target-min` tall. **Never** `--color-danger`, never accent fill, never a warning glyph.
- Unlimited depth back to draft start (D-10). No redo — a redo stack would be a second piece of state living outside the persisted log.
- No confirmation. Undo *is* the confirmation mechanism for D-08's one-click pick.
- Disabled when the log holds no picks: native `disabled`, `aria-disabled="true"`, `opacity: 0.45`, `cursor: not-allowed`. The label does not change.
- `Ctrl+Z` / `Cmd+Z` triggers undo when focus is not inside a text field. Required — the host is a scribe transcribing names called out over voice.
- Feedback is the state change itself (banner text reverts, board slot empties, species reappears in the pool) plus the polite live-region announcement.

### 4. Persistence surfaces

**(a) Storage-unavailable blocking screen** (PERS-02 / D-13). Runs the write-read-delete canary *before the draft renders*.

- Full-viewport `--color-bg` backdrop, centred panel `max-width: 640px`, `--color-surface`, `--space-7` padding, `--radius`, `border-left: 4px solid var(--color-danger)`.
- Heading at `--text-heading` in `--color-danger`; body at `--text-body`; primary CTA `Continue without saving` in accent fill.
- `role="alertdialog"`, `aria-modal="true"`, focus moved to the heading on mount and trapped inside. **No** close X, **no** Escape-to-dismiss. Acknowledgement is required (D-13).
- When the canary passes: render nothing. No banner, no toast, no confirmation of success.

**(b) Read-only tab banner** (PERS-03 / D-12). Full-width bar pinned above the top bar.

- `--color-surface`, `--hairline-w` bottom border, `--space-3` padding, text at `--text-body`, `Take over drafting here` in accent fill (it is the primary action of this state, and a read-only tab has no on-the-clock indicator to compete with).
- While read-only, the entire draft region carries the `inert` attribute — one attribute handles pointer, keyboard, and focus in a single stroke, and it is Baseline-supported. Do **not** hand-roll `pointer-events: none` plus per-element `disabled`.
- Stale-lock recovery (the holder tab crashed) swaps only the banner sentence; the button label is unchanged. The handoff and the stale-lock heartbeat are real engineering work, flagged in D-12 as a task rather than a detail.

**(c) Checkpoint prompt at draft complete** (PERS-06 / D-11). The phase's only hard milestone.

- Non-modal panel at the top of the completed-draft screen, `--color-surface`, `--space-4` padding.
- Heading, body, accent-fill `Download tournament JSON`, and a text-only secondary `Not now`.
- **Never** downloads without a click.

**(d) JSON export / import** (PERS-04, PERS-05, PERS-07). Two secondary buttons in the top bar, available at all times: `Download JSON` and `Import JSON…`.

- Import while a draft is in progress opens the `Replace the current draft?` dialog — the one destructive confirmation in the phase.
- Import into an empty state proceeds with no dialog.
- Both failure strings are in the copywriting table. A failed import leaves the current state untouched.

### 5. Export panel (EXPO-01…06 / D-09)

One panel per player. **Never** a combined block, even at two players.

- Heading `{playerName}` at `--text-heading`.
- `Copy team paste` accent-fill button, placed **above** the text.
- `<pre>` block: `font-family: var(--font-mono)` at **`--text-body`** (18/400/1.5). The paste block takes the body token, not `--text-label`: this is reading copy the host proof-reads by eye before pasting, and 14px semibold would make the blank-line separator harder to spot rather than easier. The mono family is scoped here and nowhere else; it adds no size of its own. Also `--color-surface`, `--hairline-w solid var(--color-border-strong)`, `--radius`, `--space-3` padding, `white-space: pre`, `tabindex="0"`, `aria-label="{playerName} team paste"` so keyboard users can reach and select it.
- **The paste text is visible and selectable, always.** A blocked or failing Clipboard API must never be a dead end (D-09).
- **Do not** apply `white-space: pre-line` and do not collapse whitespace — EXPO-03's blank-line record separator must render as a visible blank line. Newline-separated output silently imports only the first Pokémon; the mono family and `--text-body`'s 1.5 line-height exist so this is verifiable by eye.
- A Mega slot renders as one line, `Species @ StoneItemName` (EXPO-02), still blank-line separated from its neighbours.
- Helper text below at `--text-label` in `--color-text-muted`, naming both targets. One paste serves both — Showdown and pokebase accept the same text.
- Copy feedback: the button label swaps per the copywriting table and also fires the polite live region. The button never changes colour on success.

## Interaction & Accessibility Baseline

Applies to every surface. Non-negotiable for this phase and inherited by all later phases.

| Rule | Requirement |
|------|-------------|
| Real elements | Every clickable thing is `<button>`, `<a>`, or `<input>`. No `onClick` on a `div` or `span`, anywhere. |
| Focus visible | `outline: 3px solid var(--focus-ring); outline-offset: 2px;` on `:focus-visible`. `outline: none` is forbidden unless an equal-or-better ring replaces it in the same rule. |
| Target size | Every interactive element ≥ `--target-min` in both axes. |
| Live region | Exactly one `<div role="status" aria-live="polite">` at app root, visually hidden. Announces: turn change, undo, copy result, import result. Nothing uses `aria-live="assertive"`. |
| Turn changes | `TurnBanner` content is mirrored into the live region so the turn is announced, not only shown. |
| Document | `<html lang="en">`, one `<h1>` per screen, headings never skip a level. |
| Reduced motion | `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { transition-duration: 0.01ms !important; animation-duration: 0.01ms !important; } }`. Phase 1 has only 120ms colour transitions, so nothing is lost. |
| Motion budget | Colour and border transitions only, ≤120ms. No layout animation, no entrance animation, no pick-reveal flourish in this phase. |
| Zoom | Layout must survive 200% browser zoom without horizontal scroll on the page (the board's own horizontal scroll is intentional and exempt). |
| Images | Every `<img>` has explicit `width`/`height` and an `alt` (empty when the adjacent text already names it). |

### Layout shell

- One column, `max-width: 1600px`, centred, `--space-4` page padding.
- Vertical order: read-only banner (conditional) → sticky `TopBar` → `TurnBanner` → `BoardGrid` → `PoolGrid`.
- `TopBar` and `TurnBanner` stay on screen together while the pool scrolls, so undo and whose-turn are always visible. This is the shared-screen requirement in miniature.
- **Mechanism:** both live inside a single `.sticky-head` wrapper that carries `position: sticky; top: 0`. They are *not* each given `top: 0` individually — two siblings both pinned to `top: 0` would stack on top of each other and hide one. The wrapper also needs `display: flow-root` to stop margin collapse from leaking a gap above the pinned block. (Corrected during 01-07; the original wording specified an arrangement that cannot render.)

### Pure-core boundary (SHEL-04) — a UI rule too

No component in `src/ui/` may own a game rule. Whose turn it is, which round is current, which species remain in the pool, whether the draft is complete, and the export paste string are all **selectors** computed in `src/core/`. UI components render selector output and dispatch actions. `Date.now()`, `Math.random()`, `localStorage`, and `fetch` never appear under `src/core/`, and the CI grep enforces it. If a surface in this spec seems to need the UI to decide a rule, the selector is missing — add the selector, do not add the logic to the component.
