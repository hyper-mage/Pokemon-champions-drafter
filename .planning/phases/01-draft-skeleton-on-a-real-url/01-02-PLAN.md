<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → repository | The workflow's GITHUB_TOKEN is the only credential in the system |
| GitHub Pages CDN → public internet | Everything served is public, static, and unauthenticated by design |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-13 | Elevation of Privilege | workflow GITHUB_TOKEN scope | mitigate | Top-level `permissions` block grants only `contents: read`, `pages: write`, `id-token: write`. Explicitly no `contents: write`, asserted by the task's negative grep |
| T-01-14 | Tampering | third-party GitHub Actions in the workflow | mitigate | Only first-party `actions/*` actions are used (checkout, setup-node, configure-pages, upload-pages-artifact, deploy-pages). No community actions, no `curl \| sh` steps |
| T-01-15 | Tampering | deploying code that violates the pure-core boundary | mitigate | `deploy` job has `needs: verify`; the verify job runs `check:pure:selftest`, `check:pure`, and `test` before the artifact is ever uploaded |
| T-01-09 | Spoofing | public Pages origin | accept | Static, accountless site with no secrets in the bundle and no server-side state to impersonate |
| T-01-16 | Information Disclosure | secrets leaking into the built bundle | mitigate | The build reads no secrets; there are none in the repository. `npm run build` output is reviewed for the expected asset set only |
</threat_model>
