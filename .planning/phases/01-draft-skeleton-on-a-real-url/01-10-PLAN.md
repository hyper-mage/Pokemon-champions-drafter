<objective>
Make the JSON file the durable copy of the tournament: download at any time, import on another machine, refuse anything malformed, and offer a checkpoint at draft complete — plus the per-player export panels that finish the draft.

Purpose: PROJECT.md's Key Decisions say the JSON file is the system of record, because browser storage evaporates in at least six documented ways including Safari deleting script-writable storage after seven days idle. This is also the app's only untrusted-input boundary, and CLAUDE.md flags it as the one place validation genuinely earns its keep.
Output: Download JSON, Import JSON, the completed-draft screen, and per-player pastes.

    Tests first, and write the prototype-pollution test before the implementation.

    src/core/import-guard.ts is the app's single untrusted-input boundary. Hand-roll it:
    adding a validation library would be a third runtime dependency, which is a constraint
    violation.

    `parseTournamentFile(text, byteLength)` performs, in this order:
      1. Size gate. Reject before parsing when byteLength exceeds 5 MB. A tournament is
         tens of KB; anything larger is either corrupt or hostile.
      2. `JSON.parse` inside try/catch, using a **reviver** that drops any key equal to
         `__proto__`, `constructor`, or `prototype`. A reviver returning undefined omits
         the key entirely, which neutralises prototype pollution at the parse boundary
         rather than after it.
      3. Shape validation by explicit allow-list. Build the resulting document field by
         field from named properties. Never `Object.assign`, never spread an untrusted
         object into a trusted one, never `structuredClone` the raw parse result into
         state. Every field is copied deliberately, and unknown fields are dropped.
      4. Bounds: `log` must be an array of at most 20000 entries; every entry must have a
         string `type`, a non-negative integer `seq`, a numeric `at`, and a string
         `actorId`. `seq` values must run 0, 1, 2, … with no gaps, because the reducer
         relies on that ordering.
      5. `config.players` must be a non-empty array of `{ id: string, name: string }`, and
         `config.rounds` must be a positive integer.
      6. Delegate the version decision to `migrate`.

    Return a discriminated result, never a throw: `{ ok: true, doc }` or
    `{ ok: false, reason }` where reason is one of `tooLarge`, `notJson`, `wrongShape`,
    `newerSchema`, or `unknownSchema`. The caller maps reason to the exact UI copy.

    Also export `isValidTournament(value)` as a plain predicate for reuse by
    `persistence.load()` — replace the provisional shape check there with this guard, so
    a corrupt localStorage record gets exactly the same treatment as a hostile file.

    src/core/migrate.ts exports `SUPPORTED_SCHEMA_VERSIONS` (just `[1]` today) and
    `migrate(doc)`. Version 1 is a passthrough. A higher version is refused — never
    half-loaded — because a tool that cannot open a tournament it created is a worse
    outcome than a clear refusal. The function exists now so that future versions have an
    obvious home rather than accreting `if (doc.someNewField)` checks across the codebase.

    src/adapters/file-io.ts is the impure half:
      `downloadJson(filename, obj)` builds a Blob, creates an object URL, clicks a
      synthetic `<a download>`, and revokes the URL. Roughly fifteen lines, no dependency,
      works everywhere. Do NOT use the File System Access API as the only path — there is
      no Firefox and no Safari support, including all of iOS. Feature-detecting
      `showSaveFilePicker` as a progressive enhancement is permitted but is not required
      and should not be built in this phase.
      `readJsonFile(file)` reads a File via `file.text()` and returns both the text and the
      byte length so the guard can apply its size gate.

    Filename convention: `champions-draft-{YYYY-MM-DD}-{first 8 chars of doc.id}.json`,
    with the date taken from the clock adapter, never from inside core.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported JSON file → application state | The only genuinely untrusted input path in the entire app |
| localStorage record → application state | Same shape, same guard, different source |
| clipboard write → OS clipboard | May be blocked by permissions policy; must never be the only path to the data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | prototype pollution via `__proto__`, `constructor`, or `prototype` keys in an imported file | mitigate | `JSON.parse` reviver drops those keys at the parse boundary; the document is then rebuilt field by field from an explicit allow-list with no `Object.assign`, no spread, and no `structuredClone` of the raw parse result. Asserted by a test that checks `({}).polluted === undefined` |
| T-01-02 | Tampering | a file claiming an unknown or newer schemaVersion | mitigate | `migrate` refuses rather than half-loading, and the UI shows the specified copy. A tool that silently misreads its own old saves is worse than one that declines |
| T-01-03 | Denial of Service | oversized or deeply nested import file | mitigate | 5 MB size gate applied before `JSON.parse`, plus a 20000-entry log cap and per-entry field-type checks |
| T-01-44 | Tampering | a valid-looking file with out-of-order or gapped `seq` values driving the reducer into a bad state | mitigate | The guard requires `seq` to run 0, 1, 2, … with no gaps, matching the reducer's assumption. Rejected otherwise |
| T-01-45 | Tampering | a failed import corrupting the in-progress draft | mitigate | Validation completes fully before the store is touched; every failure path returns without mutating state, and a test asserts the in-memory document is byte-identical after a rejected import |
| T-01-05 | Tampering | corrupt localStorage record | mitigate | `persistence.load()` now runs the same `isValidTournament` guard as the file path, so the two untrusted sources get identical treatment |
| T-01-46 | Denial of Service | Clipboard API blocked by permissions policy or an insecure context | mitigate | D-09: the paste text is always visible and selectable in a focusable `<pre>`; the copy button is a convenience and its failure states are specified copy, not a dead end |
| T-01-33 | Information Disclosure | exported JSON containing player names | accept | Names are typed by the host for their own friends; the file is downloaded to the host's own machine and shared deliberately. No accounts, no PII beyond a chosen display name |
</threat_model>
