TournamentDoc {
  schemaVersion: 1
  id: string                       // crypto.randomUUID() at the edge, never in a reducer
  createdAt: number                // epoch integer, stamped at the edge
  config: {
    formatLabel: string
    players: [{ id, name }]        // Phase 1: p1/Player 1 and p2/Player 2, hardcoded scaffolding
    rounds: 6
    rosterVersion: string          // the snapshot's regulation label
    rosterChecksum: string
  }
  rng: { seed: number, cursor: number }
  log: Action[]
}

Action = { type, seq, at, actorId, ...payload }   // seq monotonic, at epoch ms, actorId 'host'

Action types this phase defines. All four exist from day one, including pickUndone,
which nothing dispatches until plan 07 — rule 15 requires the compensating action type
to exist and be reducible now so log-popping stays an optimization, not a design:
  'pool/built'        { ids: string[], rosterVersion: string, checksum: string }
  'draft/started'     { order: string[] }        // materialized from the seed, not re-derived
  'draft/pickMade'    { playerId, monId, round, pickIndex }
  'draft/pickUndone'  { targetSeq: number }

Phase 1 pick order: strict alternation. Round r runs order[0] then order[1].
Six rounds, twelve picks, six per player.

    - Folding a log prefix equals the state before the removed action was applied — this is what makes undo a re-fold rather than an inverse patch

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI event handlers → document | The only place a human action becomes persisted state; guarded by canApply |
| impure edge (clock, id, seed) → action payloads | Ambient values are stamped at the edge and never read inside a reducer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-28 | Tampering | draft state mutated outside the log | mitigate | dispatch is the only write path; the acceptance criteria assert exactly one `log.push` site in the codebase and zero log mutation anywhere under src/ui or src/app.tsx |
| T-01-29 | Tampering | an illegal pick entering the log | mitigate | canApply runs before every append and a rejected action never touches the log; notInPool, notYourTurn, and draftComplete are all covered by tests |
| T-01-30 | Tampering | non-reproducible state after reload | mitigate | SHEL-07: the seed lives in the document, randomness comes only from the pure nextInt, and the resolved starting order is materialized into draft/started so replay reads the recorded result |
| T-01-04 | Information Disclosure | player names and species names rendered to the DOM | mitigate | Preact text children only; `npm run check:nohtml` gates the build against innerHTML and dangerouslySetInnerHTML anywhere under src/ |
| T-01-31 | Denial of Service | unbounded log growth | accept | A full eight-player tournament is 350-500 actions and a complete re-fold is sub-millisecond. Plan 10's import guard caps log length on untrusted input, which is the only path where an attacker controls it |
</threat_model>
