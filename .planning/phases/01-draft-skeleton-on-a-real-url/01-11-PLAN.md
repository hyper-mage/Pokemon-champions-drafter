<!-- Decisions this plan implements -->
D-14  A hand-written cache-first service worker, roughly 30 lines. CLAUDE.md and STACK.md
      both reject `vite-plugin-pwa` explicitly: Workbox plus its config surface is far more
      than a small cache-first worker.
D-15  Versioned cache name, activate on next load. The new worker installs in the
      background, wipes old caches on activate, and takes over the next time a tab opens.
      NO update banner. NO `skipWaiting`, NO `clients.claim` — that lifecycle is the
      easiest part of a service worker to get subtly wrong, and a host mid-draft should
      never be disrupted. One stale session after a deploy is accepted.
D-16  Precache EVERYTHING on install: app shell, roster JSON, and all roughly 310 sprites,
      before activation. Offline is total from the second visit onward. Accepts about 1 MB
      and 310 requests on the very first load.
D-17  Double-clicking index.html from a clone does NOT have to work. The hosted Pages link
      is the delivery path, and a service worker cannot run from file:// in any case
      because it requires a secure context.
D-18  The "literally double-click index.html" test still runs, but its purpose is to
      DOCUMENT the behaviour, not to fix it. Record what happens.

  <action>
    Write `public/sw.js` by hand. Keep it under 80 lines. It has exactly three listeners and
    no build-tool involvement beyond a single token substitution.

    At the top, two placeholders the post-build script replaces:
      a version string token, and `__PRECACHE_MANIFEST__` which becomes a JSON array of
      URLs. Ship the file with the tokens present so the un-injected file is obviously
      broken rather than silently half-working.

    Cache name: `champions-drafter-<version>`, where version is the injected build version.

    `install`: `event.waitUntil` opening the cache and `addAll`-ing the full manifest. D-16
    means the worker does not activate until every asset is cached. Note the accepted
    consequence: a single failed request fails the whole install, and the visitor simply
    gets no worker until their next visit. That is the chosen trade.

    `activate`: `event.waitUntil` deleting every cache whose name starts with
    `champions-drafter-` and does not equal the current name. Do NOT call `self.skipWaiting()`
    and do NOT call `self.clients.claim()`. The new worker waits, and takes over on the next
    tab open. A host mid-draft is never disrupted (D-15).

    `fetch`: cache-first. For same-origin GET requests only, respond from the cache when
    present, otherwise fall through to the network. Do not cache non-GET, do not cache
    cross-origin, and do not implement runtime cache-population — the precache is the whole
    inventory and anything outside it is a bug worth seeing rather than papering over.

    Write `scripts/build-sw-manifest.mjs` to run after `vite build`. It walks `dist/`
    recursively, collects every file except `sw.js` itself and `.nojekyll`, converts each
    path to a URL rooted at the Vite base `/Pokemon-champions-drafter/`, always includes the
    base path itself so a bare visit to the directory URL is cached, and substitutes both
    tokens in `dist/sw.js`. Derive the version from a content hash over the sorted manifest,
    so an unchanged build produces an unchanged version and a changed build always changes
    it.

    Print the manifest size and the total byte count. Fail with a non-zero exit if the
    manifest contains fewer than 300 entries — that is the tripwire for the sprite directory
    silently not being copied, which would otherwise ship a worker that thinks it is
    offline-complete when it is not.

    Wire it into `npm run build` as a post-build step so the workflow picks it up
    automatically, and confirm the workflow's upload step still uploads `dist`.

    Register in `src/main.tsx`, guarded by `'serviceWorker' in navigator` and
    `import.meta.env.PROD`. Register with an explicit `scope` equal to
    `import.meta.env.BASE_URL` so the worker's scope matches the Pages sub-path rather than
    the domain root — a root-scoped worker on a project Pages site is both wrong and
    something the platform will refuse. Register on the `load` event so the first paint is
    never delayed by 310 cache writes.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service worker → every request from the origin | An activated worker intercepts fetches for its entire scope and is the highest-privilege client-side code in the app |
| stale cache → running app | A worker can serve indefinitely old code if its lifecycle is wrong |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Elevation of Privilege | service worker scope | mitigate | Registered with an explicit `scope` equal to `import.meta.env.BASE_URL`, so the worker controls only `/Pokemon-champions-drafter/` and not the whole `github.io` origin. No `importScripts`, no dynamic code loading, no runtime cache population |
| T-01-47 | Tampering | a stale worker serving indefinitely old application code | mitigate | Cache name carries a content-derived build version; `activate` deletes every non-matching `champions-drafter-` cache. D-15 accepts exactly one stale session and the checkpoint verifies a new tab gets the new build |
| T-01-48 | Denial of Service | one failed asset request aborting the whole `addAll` install | accept | The chosen D-16 trade: the visitor gets no worker until their next visit and the app still works online. Preferred over an inventory the worker wrongly believes is complete |
| T-01-49 | Tampering | the precache manifest silently missing the sprite directory | mitigate | `scripts/build-sw-manifest.mjs` exits non-zero when the manifest has fewer than 300 entries, and the automated verify asserts both a `sprites/` and a `data/roster.` URL are present |
| T-01-50 | Spoofing | cross-origin responses entering the cache | mitigate | The fetch handler serves only same-origin GET requests from the cache and never populates the cache at runtime; the manifest is generated exclusively from `dist/` |
</threat_model>
