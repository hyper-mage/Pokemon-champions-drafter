  <action>
    src/adapters/persistence.ts is impure by design and lives in adapters. It must never be
    imported from src/core.

    Storage key: a single constant `champions-drafter:tournament`. The persisted record is
    `{ schemaVersion, generation, savedAt, doc }` — not the bare document. `generation` is a
    monotonically increasing integer bumped on every successful write, and it is what plan
    09's ownership lock and any future clobber detection read.

    `save(doc)` serializes and writes inside a try/catch. On QuotaExceededError or
    SecurityError it does NOT retry silently: it flips an exported `savingBlocked` signal to
    true and surfaces the same warning the canary would have. On success it clears the flag
    and records the timestamp.

    `load()` reads and parses inside a try/catch, returns null on absent or unparseable
    data, and returns null rather than throwing when `schemaVersion` is unrecognised. A
    corrupt record must never be allowed to overwrite a good one or to half-load — plan 10's
    import guard is reused here once it exists; for now, validate that the parsed value is
    an object with an array `log` and an object `config`, and reject anything else.

    `startAutosave(store)` subscribes to the store and schedules a save on a trailing
    debounce of 300ms. Picking is a burst activity and a full document is only tens of KB,
    so 300ms keeps writes cheap without ever letting a pick sit unsaved for long.

    Register a `pagehide` listener that flushes any pending debounced save synchronously.
    This is the one moment where localStorage's synchronous API is the feature rather than
    the drawback: a write started in pagehide completes, whereas an async write can be lost.
    Use `pagehide` rather than `unload`, which is unreliable and blocks bfcache.

    Call `navigator.storage.persist()` once on the first meaningful interaction (the first
    pick). Persistent-mode origins are exempt from LRU eviction. Treat the boolean result as
    advisory: log it, surface it nowhere in Phase 1, and never gate behaviour on it.

    Wire it up in src/app.tsx: on boot, call `load()`. If a document comes back, adopt it
    into the store instead of creating a fresh tournament. Otherwise call
    createTournament(snapshot). Then call startAutosave.

    Be explicit in the SUMMARY about what this does NOT solve: Safari deletes all
    script-writable storage after seven days without interaction on the origin, and that
    hits localStorage and IndexedDB equally. The durable answer is the JSON file, which
    arrives in plan 10.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → app state on boot | Stored bytes are attacker- or corruption-modifiable and are read back as authoritative |
| browser storage policy → app | Private mode, enterprise policy, quota, and Safari's seven-day eviction all silently remove data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | corrupt, truncated, or hand-edited localStorage record | mitigate | `load()` parses inside try/catch, validates that `log` is an array and `config` is an object, rejects an unrecognised `schemaVersion`, and returns null rather than half-loading. Plan 10 upgrades this to the full import guard |
| T-01-07 | Denial of Service | QuotaExceededError on write, including Safari private mode where the first setItem throws | mitigate | Every write is wrapped in try/catch; the first failure flips `savingBlocked` and surfaces the D-13 warning rather than retrying silently |
| T-01-32 | Repudiation | host believes the draft is saved when it is not | mitigate | PERS-02 canary runs before the draft renders and blocks with an acknowledge-required screen; a mid-session write failure raises the same warning |
| T-01-33 | Information Disclosure | tournament data readable from devtools and localStorage | accept | Friends on a shared screen; there is no secret in Phase 1. Blind bans in Phase 4 will state honestly that hidden means hidden from the screen, not from a determined player |
| T-01-34 | Denial of Service | Safari deleting all script-writable storage after seven days idle | accept | Cannot be prevented by any storage engine; `navigator.storage.persist()` is called as advisory mitigation and the durable answer is the JSON file export in plan 10 |
</threat_model>
