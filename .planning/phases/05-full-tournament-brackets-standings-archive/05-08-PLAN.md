## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 5. Not in `As a … I want to … so that …` form and not
rewritten here — run `/gsd mvp-phase 5` if the three-slot form is wanted.

> The night runs past the draft — round robin, a seeded cut, a single-elimination bracket, results
> recorded and correctable — and the finished tournament stays readable and re-runnable after the
> Champions roster rotates

**Slice delivered by this plan:** the log learns to carry a tournament. After it, a result can be
recorded, corrected, voided, cut from and reopened — and every one of those survives a download and
a re-import, joins the one undo stack, and is refused by the reducer when the rules say no. The
surfaces that dispatch these are 05-10, 05-11 and 05-13; this is the plan that makes those surfaces
possible without inventing a second write path.

<precedence>
`05-UI-SPEC.md:44` states "There is no `05-RESEARCH.md`." It is dated a day earlier. **RESEARCH
governs mechanism; UI-SPEC governs copy, layout and tokens.** This plan is entirely mechanism.

**D-10 is followed literally: two actions, not one.** RESEARCH records honestly that a single
`tournament/matchRecorded { voids: number[] }` would be atomic by construction, would need no
`causedBySeq` and no pairing arm in `removalIndices`, and would satisfy every *stated purpose* of
D-10. D-10 is a locked decision and its words are "ALSO appends an explicit clearing action naming
the matches voided" — specific enough that reading it as a payload field would be an override rather
than an interpretation. The atomicity risk is nil in practice: both dispatches are synchronous in one
event handler and autosave is a 300ms trailing debounce (`persistence.ts:52`), so no partial
correction can reach storage. **Do not substitute the single-action shape.**
</precedence>

// src/core/actions.ts
export const TOURNAMENT_MATCH_RECORDED = 'tournament/matchRecorded';
export const TOURNAMENT_RESULTS_VOIDED = 'tournament/resultsVoided';
export const TOURNAMENT_CUT_TAKEN = 'tournament/cutTaken';
export const TOURNAMENT_TIEBREAK_ORDERED = 'tournament/tiebreakOrdered';
export const TOURNAMENT_REOPENED = 'tournament/reopened';

export interface MatchRecordedPayload {
  type: typeof TOURNAMENT_MATCH_RECORDED;
  matchId: string;      // rr:{i}:{j} or br:{round}:{slot}
  winnerId: string;
  loserId: string;      // CARRIED, never derived
  winnerGames: number;  // 1..2
  loserGames: number;   // 0..1
  metric: number;       // 0..MAX_MATCH_METRIC
}
export interface ResultsVoidedPayload {
  type: typeof TOURNAMENT_RESULTS_VOIDED;
  targetSeqs: number[];
  causedBySeq: number;
}
export interface CutTakenPayload { type: typeof TOURNAMENT_CUT_TAKEN; seeds: string[]; }
export interface TiebreakOrderedPayload {
  type: typeof TOURNAMENT_TIEBREAK_ORDERED;
  playerIds: string[];
}
export interface ReopenedPayload { type: typeof TOURNAMENT_REOPENED; }

export function matchRecorded(/* six named fields */): MatchRecordedPayload;
export function resultsVoided(targetSeqs: readonly number[], causedBySeq: number): ResultsVoidedPayload;
export function cutTaken(seeds: readonly string[]): CutTakenPayload;
export function tiebreakOrdered(playerIds: readonly string[]): TiebreakOrderedPayload;
export function reopened(): ReopenedPayload;

export function isMatchRecordedAction(action: AnyAction): action is MatchRecordedAction;
export function isResultsVoidedAction(action: AnyAction): action is ResultsVoidedAction;
export function isCutTakenAction(action: AnyAction): action is CutTakenAction;
export function isTiebreakOrderedAction(action: AnyAction): action is TiebreakOrderedAction;
export function isReopenedAction(action: AnyAction): action is ReopenedAction;

// src/core/import-guard.ts
export const MAX_MATCH_METRIC = 18;                       // six Pokémon x three games
const MATCH_ID_PATTERN = /^(rr:\d+:\d+|br:\d+:\d+)$/;     // module-private, checked in buildLogEntry
