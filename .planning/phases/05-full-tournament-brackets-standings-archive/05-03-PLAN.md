rewritten here — run `/gsd mvp-phase 5` if the three-slot form is wanted.

> The night runs past the draft — round robin, a seeded cut, a single-elimination bracket, results
> recorded and correctable — and the finished tournament stays readable and re-runnable after the
> Champions roster rotates

**Slice delivered by this plan:** the round robin and the standings become executable and testable
before any pixel exists — every pairing, how many are left, who is ahead, and which tiebreak link is
currently deciding the order. `05-UI-SPEC` §Pure-core boundary forbids a component from owning any
of those, and every one of them is provable at 4, 5, 6, 7 and 8 players in a `node` environment with
zero mocks, which is the observable payoff of the purity rule.

<precedence>
`05-UI-SPEC.md:44` states "There is no `05-RESEARCH.md`." It is dated a day earlier. **RESEARCH
governs mechanism; UI-SPEC governs copy, layout and tokens.** This plan is entirely mechanism, so
RESEARCH §Standings is the specification; `05-UI-SPEC.md` §6 supplies only the five-row note table
that `decidedBy` must map onto 1:1.

**Two rulings this plan makes, both flagged by RESEARCH as open:**

1. **A still-tied block shares one position number.** Three players tied for third read `3 3 3`, not
   `3 4 5`. `3 4 5` asserts an order the tool has explicitly refused to compute and the row's own
   note (`Tied — order these yourself`) contradicts. This is a `StandingsRow.position` rule, decided
   here and consumed by 05-11.
2. **The automatic chain stops at a two-way block.** Head-to-head applies wherever a block has
   narrowed to exactly two — including a block that reached two via the metric link — and never to
   three or more, which go straight to D-13's override. `05-UI-SPEC.md` §6 already decided this and
   `PROJECT.md` §Out of Scope rejects automatic multi-link chains; it is restated because the
   "block is size 2" framing is not the same rule as "the record group is size 2" and the difference
   is testable.
</precedence>

```ts
// src/core/tournament.ts
export type TournamentStage = 'notRunning' | 'roundRobin' | 'bracket';
export function selectTournamentStage(state: DraftState): TournamentStage;

export interface RoundRobinMatch { matchId: string; aId: string; bId: string; }
/** `rr:{i}:{j}`, 0-based indices into `config.players`, `i < j`. */
export function selectRoundRobinMatches(state: DraftState): readonly RoundRobinMatch[];

/** Pair count minus the recorded ones. The `{k}` in `{k} of {n} matches still to play.` */
export function selectRemainingMatchCount(state: DraftState): number;

export interface StandingsRow {
  playerId: string;
  /** Shared across the members of an unresolved block — `3 3 3`, never `3 4 5`. */
  position: number;
  wins: number;
  losses: number;
  /** `0` at `draftAndBrackets` and never rendered there (D-02). */
  metric: number;
  decidedBy: 'record' | 'metric' | 'headToHead' | 'hostOrder' | 'tied';
}
export function selectStandings(state: DraftState): readonly StandingsRow[];

/** The standings order IS the seeding order. `selectStandings(state).map(r => r.playerId)`. */
export function selectSeeding(state: DraftState): readonly string[];
```
