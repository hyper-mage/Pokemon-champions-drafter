## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 5. Not in `As a … I want to … so that …` form and not
rewritten here — run `/gsd mvp-phase 5` if the three-slot form is wanted.

> The night runs past the draft — round robin, a seeded cut, a single-elimination bracket, results
> recorded and correctable — and the finished tournament stays readable and re-runnable after the
> Champions roster rotates

**Slice delivered by this plan:** a host can configure the shape of the night after the draft and see
what each choice means. This is the first surface in the phase and the first point at which a real
person can do something they could not do before: choose `Draft, brackets and match log`, choose
whether the number is Pokémon left or KO difference, choose best-of-one through the pool and
best-of-three in the cut, and read how many round-robin matches that will be.

<precedence>
`05-UI-SPEC.md:44` states "There is no `05-RESEARCH.md`." It is dated a day earlier. **RESEARCH
governs mechanism; UI-SPEC governs copy, layout and tokens.** This plan is almost entirely copy,
layout and tokens, so `05-UI-SPEC.md` §1 and §Copywriting are the specification and every string is
byte-for-byte from them.
</precedence>

<objective>
Grow the `Depth` group from one `SegmentedControl` plus a static note into a group of four controls
with a note that changes with the selection.

Purpose: D-01 makes the difference between the two deeper tiers a *specific* one — the numeric field
and the editable history — and one sentence under the group cannot state three different outcomes.
D-04 and D-08 add three fields that only mean something at particular depths, and the project's
established answer to "a control that is unavailable right now" is to render it inert with the reason
visible, never to hide it.

Output: three new controls, three new copy constants, a per-option note, a round-robin size line, and
the tests that pin the inertness table.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host input → the document `handleStart` writes | The config screen is the only place a tournament document is created. A value it can write that `isValidTournament` would refuse is a tournament the host cannot resume. |
| `checkFeasibility` → the sentence on screen | One authority on satisfiability. A second sentence about brackets and player counts anywhere on this screen would be free to disagree with it. |
| an inert control's ARIA → its click handler | An `aria-disabled` control that still acts is a lie told to exactly the users who depend on the attribute. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-21 | Tampering | a config value the import guard would refuse | mitigate | All three new fields are closed string unions rendered as `SegmentedControl`s, so the screen cannot produce a value outside the union that 05-01's `buildConfig` accepts. There is no free-text or numeric input among them, which is why no bound constant is needed here. |
| T-05-22 | Elevation of privilege | an inert control that still changes the config | mitigate | Every inert change handler returns early, on `SchedulePreview.tsx:1137-1144`'s stated model, and a test asserts the written config is unchanged after interacting with an inert control. The ARIA and the behaviour cannot drift. |
| T-05-23 | Information disclosure | injected markup through a copy string | mitigate | Every string is a module constant rendered as a text child; Preact escapes text children and `npm run check:nohtml` forbids `innerHTML` and `dangerouslySetInnerHTML` across all of `src/`. No copy string is interpolated into markup. |
