## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 5. Not in `As a … I want to … so that …` form and not
rewritten here — run `/gsd mvp-phase 5` if the three-slot form is wanted.

> The night runs past the draft — round robin, a seeded cut, a single-elimination bracket, results
> recorded and correctable — and the finished tournament stays readable and re-runnable after the
> Champions roster rotates

**Slice delivered by this plan:** the night finishes inside the tool. After this plan a group plays the
bracket, sees the byes their seeding earned, records each match through the dialog they already know,
and watches a champion get named on the card the room is already looking at.

<precedence>
`05-UI-SPEC.md:44` states "There is no `05-RESEARCH.md`." It is dated a day earlier. **RESEARCH
governs mechanism; UI-SPEC governs copy, layout and tokens.** §9, §10 and §Copywriting are the
specification here; the bracket's arithmetic is 05-06's and is consumed, not re-derived.

**Scope fence, restated because this is the plan where it bites.** `PROJECT.md` §Out of Scope,
`05-CONTEXT.md` §Phase Boundary and the ROADMAP's own note all agree, and `05-RESEARCH.md` §Scope
Fence exists so a planner can point at it. **Out, unconditionally: double elimination, Swiss,
consolation and third-place brackets, and Buchholz.** PROJECT.md's own words are that
"losers-bracket layout is where bracket rendering code goes to die." A losers bracket is not a variant
of this CSS Grid; it is a second bracket with its own drop-down edges. If any of the following appears
in an implementation, it is a scope breach to escalate rather than a design choice: a `MatchResult`
field named `bracketSide`, `losersRound` or `dropDown`; a bracket data structure with more than one
root; a third-place card.
</precedence>

<objective>
Draw the bracket, name the champion on it, and make a finished tournament read-only without hiding
anything.

Purpose: `05-UI-SPEC.md` §Design System rules out the two obvious implementations at once — no icon
library (this phase needs zero glyphs: a bye is the word `Bye`, a champion is the word `Champion`) and
no SVG connector layer (it would have to know where each card landed, which CSS Grid decides at layout
time). `align-content: space-around` is what centres each round's cards against the pair feeding them
without any code knowing a card's pixel position.

Output: two components for the bracket, one for the finished state, and the inert pass across every
result control.
</objective>
