## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 5. Not in `As a … I want to … so that …` form and not
rewritten here — run `/gsd mvp-phase 5` if the three-slot form is wanted.

> The night runs past the draft — round robin, a seeded cut, a single-elimination bracket, results
> recorded and correctable — and the finished tournament stays readable and re-runnable after the
> Champions roster rotates

**Slice delivered by this plan:** a host can refresh the roster to a new regulation from inside the
app, can load one from a file with no network at all, and is warned when the snapshot they are about
to start a night on has expired. That is the whole of the roster half of the phase's success
criterion 5, and after this plan it works end to end.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a host's file picker → the rendered roster | REFR-02's input crosses into the app here. The validator is 05-04's; this surface must not add a second path around it. |
| a fetched snapshot → what a new tournament is created against | A successful refresh changes the roster the next document pins itself to. |
| the `inert` shell gate → every new control | A read-only tab must reach none of them. |
| an untrusted `regulationLabel` / `validUntil` → the DOM | Both come from a file that may have been supplied by the host. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-31 | Tampering | a roster file bypassing validation through the UI | mitigate | `RosterRefresh` calls `readRosterFile`, which routes through the same `parseSnapshotStrict` as the fetch path. The component contains no `fetch` and no parse of its own — pinned by `grep -c "fetch(" … returns 0`. One validator, two entry points. |
