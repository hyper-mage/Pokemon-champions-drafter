## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 5. Not in `As a … I want to … so that …` form and not
rewritten here — run `/gsd mvp-phase 5` if the three-slot form is wanted.

> The night runs past the draft — round robin, a seeded cut, a single-elimination bracket, results
> recorded and correctable — and the finished tournament stays readable and re-runnable after the
> Champions roster rotates

**Slice delivered by this plan:** a night stops dead-ending. After this plan a host can finish a
tournament, start another one, and still open the first from the landing screen weeks later — with its
log, its recap and its exports intact.

<precedence>
`05-UI-SPEC.md:44` states "There is no `05-RESEARCH.md`." It is dated a day earlier. **RESEARCH
governs mechanism; UI-SPEC governs copy, layout and tokens.** §12, §Amendment 1 and §Copywriting are
the specification for everything visible here; the storage shape was ruled in 05-09 and is not
revisited.

**The library is not simplified back to one slot.** `05-CONTEXT.md` §Specific Ideas is explicit: the
multi-tournament library is the owner's deliberate expansion, chosen over the one-slot design **after**
the eviction cost was stated, and "the correct response to the eviction risk is to keep offering the
download at every filing point (D-15), not to remove the library." Every filing surface in this plan
therefore carries a download.
</precedence>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a library entry's document → the DOM | Every string in a row heading and description comes from a document that may have been imported or hand-edited. |
| the filing gesture → two storage writes | The library and the live slot are separate keys and can partially fail; ordering decides which one a failure costs. |
| the eviction confirm → an irreversible drop | The only path in the app that removes a whole tournament from storage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-64 | Information disclosure | injected markup through a `formatLabel` or a champion's name in a library row | mitigate | Rows render every value as a Preact text child, which escapes, and `npm run check:nohtml` forbids `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `dangerouslySetInnerHTML` across all of `src/` in CI before deploy. Row descriptions are composed as strings and rendered as text, never as markup. |
| T-05-65 | Repudiation | a filing gesture that loses the live document | mitigate | The library is written first and the live slot second; a `quotaFailed` outcome stops the gesture with the live document untouched, and a test makes the write throw and asserts exactly that. This is the ordering rule `library.ts`'s header states and this plan is its only caller. |
| T-05-66 | Denial of service | an at-cap eviction discovered by catching a quota error | mitigate | `oldestEntry()` is consulted **before** the write and the eviction confirm names the tournament and offers its download. Declining leaves the library at twelve entries, asserted by test. D-16's stated reason is that a quota failure lands at the worst possible moment — while the host is trying to save a night. |
| T-05-67 | Information disclosure | the `savingBlocked` banner trained out of usefulness | mitigate | A library quota failure returns its own outcome and never raises `savingBlocked`; a `git diff` acceptance criterion pins that no new raise is added. That signal fires the one banner a host must read. |
| T-05-68 | Tampering | a poisoned library entry rendering as a valid row | mitigate | `listLibrary` (05-09) routes every entry through `isValidTournament` plus `migrate` and drops the ones that fail, so a row is only ever rendered for a document that folds. The component performs no parsing of its own. |
| T-05-69 | Elevation of privilege | a read-only tab filing or evicting | mitigate | The library section and both row actions render inside the existing `inert` shell gate; the confirms render outside it, as the existing dialogs do, but are only reachable from controls inside it. No new ownership machinery. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing; `package.json` is not modified. No virtualization for twelve rows — `05-UI-SPEC.md` §Layout Budget sizes the section against the cap deliberately. |
</threat_model>
