<precedence>
`05-UI-SPEC.md:44` states "There is no `05-RESEARCH.md`." It is dated a day earlier. **RESEARCH
governs mechanism; UI-SPEC governs copy, layout and tokens.** Both halves of that split bite in this
plan and they resolve in opposite directions, which is why the ruling is written out here.

**RULING — the library is a new module with its own key. `src/adapters/persistence.ts` is not
modified anywhere in Phase 5.**

`05-UI-SPEC.md` §Pure-core boundary item 4 reads "The library's storage — `src/adapters/persistence.ts`".
`05-RESEARCH.md` §The Library recommends a new `src/adapters/library.ts` with a separate
`localStorage` key. `05-PATTERNS.md` §`src/adapters/library.ts` flags the conflict and recommends
following RESEARCH, reading the UI-SPEC line as a **layer** statement — "this is adapter work, not
core work" — rather than a filename ruling. **That reading is adopted**, for RESEARCH's four reasons,
each of which the alternative costs:

1. **No migration at all.** An older install simply has no library key, which yields an empty library,
   which `05-UI-SPEC.md` §12 already specifies renders nothing. The CONTEXT's discretion question
   "what does an older record look like" is answered by making the question not arise.
2. **`generation` is untouched.** `loadIfNewer` compares it (`persistence.ts:323-350`) to stop a
   promoted read-only tab clobbering the owner's picks. Reshaping `PersistedRecord` would put that
   check inside a restructure for zero benefit.
3. **Two version surfaces stay independent** — the document's `schemaVersion` (5 after 05-01) and the
   library wrapper's own (1). The CONTEXT names this as a discretion item; separate keys are what make
   them separable.
4. **`tab-lock.ts` uses `BroadcastChannel`, not the `storage` event**, so a new key produces no
   cross-tab side effects.

The UI-SPEC's actual UI contract — a list on the landing screen, a filing confirm, an at-cap eviction
confirm, and the cap number — is followed exactly and is unaffected by where the bytes live.

**The cap is 12 and is not re-derived.** `05-UI-SPEC.md` §The Library Cap measures a synthetic
worst case at 21,572 characters for a 153-action document, projects roughly 65 KB at PROJECT.md's
500-action upper bound, budgets 80 KB, and lands at 1.04 MB against a conservative 5 MB — 21% used.
Do write all three defences into the constant's doc block; do not recompute them.
</precedence>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a `localStorage` value → a folded document | The library key is untrusted input in exactly the way an imported file is: anything on the machine can write it. |
| the library write → the live document's slot | Two `setItem` calls that can partially fail. Ordering decides which one a failure costs. |
| `LIBRARY_CAP` → the sentence a host reads before losing a night | The number in the dialog and the number the adapter enforces must be one number. |
