## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 3 — **note for the developer: this Goal line is not
written in `As a … I want to … so that …` form.** It was not rewritten here, because inventing a
user story the roadmap does not contain would put words in the product owner's mouth. Run
`/gsd mvp-phase 3` if the three-slot form is wanted.

> The draft becomes the one the spec describes — composition requirements compile into a round
> schedule that types the team slots, players bid priority cards for turn order over that visible
> schedule, and swaps can only take something the target slot allows.

**Slice delivered by this plan:** the host opens the config screen, sets a swap budget per player
and a number of swap rounds, starts a tournament, closes the browser, and comes back to a document
that still carries both. A Phase 2 save opened by this build is upgraded rather than refused.

<objective>
Bump the document to schema 3 and give the host the two swap numbers.

Purpose: every surface in this phase renders a field this plan adds. The schema bump cannot be
half-shipped — a document written with three of the four fields is a document `migrate` has no arm
for — so it lands once, in one plan, across all four sites that read a config: `migrate.ts`,
`import-guard.buildConfig`, `adapters/persistence.ts` and `store.ts`'s creation path via
`ConfigScreen.handleStart`.

Output: `SCHEMA_VERSION = 3`, four new `TournamentConfig` fields, one new `DraftState` field, a
`migrateV2ToV3` arm, bounds for every new field on the untrusted boundary, and the `Swaps` config
group.
</objective>
