## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 3 — this Goal line is not in `As a … I want to … so
that …` form and was not rewritten here; run `/gsd mvp-phase 3` if the three-slot form is wanted.

> The draft becomes the one the spec describes — composition requirements compile into a round
> schedule that types the team slots, players bid priority cards for turn order over that visible
> schedule, and swaps can only take something the target slot allows.

**Slice delivered by this plan:** the host sets `Megas required per team` to 2, starts a draft, and
the board's `R1` and `R2` headers say `Mega` while `R3`–`R6` do not. The schedule is in the log, so
it is still that schedule after a reload, an export and a re-import.

<objective>
Compile the rule list into a round schedule, materialize it into the log at Start, and render it on
the board.

Purpose: this is the phase's load-bearing mechanism. Every later plan reads `selectRoundKind` —
the Mega-round pool filter, the swap predicate, the export stone. It lands before any of them and
its exit gate is that `selectRoundKind(state, r)` answers correctly for every `r`.

Output: `src/core/compile.ts`, the `schedule/compiled` action family in all five places plus the
import guard's sixth, `DraftState.schedule` written by the reducer, three selectors, a third
dispatch in `createTournament`, and typed board headers.
</objective>
