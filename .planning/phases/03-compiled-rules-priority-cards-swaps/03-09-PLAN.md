## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 3 — this Goal line is not in `As a … I want to … so
that …` form and was not rewritten here; run `/gsd mvp-phase 3` if the three-slot form is wanted.

> The draft becomes the one the spec describes — composition requirements compile into a round
> schedule that types the team slots, players bid priority cards for turn order over that visible
> schedule, and swaps can only take something the target slot allows.

**Slice delivered by this plan:** the third player in a round sees two of their four remaining cards
struck through with a reason, because playing either would leave the fourth player with nothing
legal — and when the host types the wrong card, one undo takes it back.

<objective>
Constrain the card offer so CARD-04's deadlock cannot be entered, and make undo cover the whole log.

Purpose: 03-CONTEXT found a real, reachable deadlock — three players, three rounds, and a player
holding only values already down. D-21's answer is the phase's answer to everything: constrain the
offer so the invalid state is unreachable, rather than validate and reject. CONTEXT requires this be
a test, not a comment.

Output: Hall's condition in `src/core/cards.ts`, the inert card face, undo generalized to the last
undoable action with a compound removal for an automatic resolution, and `Undo last move`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported document → the card offer | An imported or hand-edited log can arrive already deadlocked, with a player holding only values already down. |
| the host's keyboard → the log | The most likely real-world failure PROJECT.md names is a host typing what someone called out over voice. Undo is the only defence. |
| read-only tab → `store.undo` | A second tab must not be able to unwind the owner's draft. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-33 | Denial of Service | the card offer | mitigate | An imported document that is already deadlocked would otherwise present a screen with zero legal actions. `playableValues` lifts the constraint for that one play and the panel states why, so the draft can always continue. Asserted by test. |
| T-03-34 | Denial of Service | `playableValues` | mitigate | Bounded by construction: at most `2^(players-1)` subset unions per candidate and at most `rounds` candidates, with `players` and `rounds` both bounded by the import guard's caps. Pinned by a sub-10ms timing assertion at 8 players and 6 rounds. |
| T-03-35 | Tampering | undo across an automatic resolution | mitigate | The compound removal makes the "undo does nothing, or loops" state unreachable. `removedCount` reports the true step size to the confirm, so the host is told two things are being removed rather than discovering it. |
| T-03-36 | Tampering | `store.undo` in a second tab | mitigate | The `isOwner()` gate is unchanged and re-asserted by test. Undo remains the one deliberate second write path and still re-folds rather than reversing. |
| T-03-37 | Tampering | the reducer's `cardNotPlayable` backstop | mitigate | The rule is enforced twice by design: the offer excludes the card, and `canApply` refuses it. A rejection reaching a user means the two disagree, which is a bug rather than a user-facing state. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing. The CARD-04 check is hand-written Hall's condition — a matching library would be a third runtime dependency and a constraint violation. |
