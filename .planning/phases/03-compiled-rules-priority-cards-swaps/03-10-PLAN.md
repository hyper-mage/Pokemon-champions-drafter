## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 3 — this Goal line is not in `As a … I want to … so
that …` form and was not rewritten here; run `/gsd mvp-phase 3` if the three-slot form is wanted.

> The draft becomes the one the spec describes — composition requirements compile into a round
> schedule that types the team slots, players bid priority cards for turn order over that visible
> schedule, and swaps can only take something the target slot allows.

**Slice delivered by this plan:** the player on the clock clicks their own round-1 Mega slot, the
pool restates itself as `Swapping Blastoise out of round 1` filtered to species that can still Mega,
they pick one, confirm, and Blastoise goes back into the pool for everyone — and they still make
their round pick.

<objective>
Make a swap possible mid-draft, and make the target slot's predicate the thing that filters the
offer.

Purpose: this is the plan the whole phase was ordered around. The compiler removed runtime
validation, so a swap built without typed slots could silently violate a composition rule with
nothing left to catch it. Slot first, then pool: SWAP-05 becomes true by construction rather than by
rejection.

Output: `swap/made` in all five places, an `apply` arm that **replaces** the pick rather than
appending, two selectors, a swappable board cell and the confirm it opens.
</objective>

export const SWAP_MADE = 'swap/made';

export interface SwapMadePayload {
  type: typeof SWAP_MADE;
  playerId: string;

  round: number;

  state: DraftState,

  slotIndex: number,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported JSON → `buildLogEntry` | A new action type with five fields crosses here, including one (`swapRound`) whose consumer does not exist until 03-11. |
| imported document → `apply(SWAP_MADE)` | A log can contain a swap whose `outMonId` does not match the slot it names, or one into a species the slot's predicate forbids. |
| the shared screen → the pool | A swap returns a Pokémon to a pool everyone is drafting from, so a wrong swap affects every player, not just the swapper. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-38 | Tampering | `apply(SWAP_MADE)` | mitigate | The arm is self-describing: it replaces the pick only when `playerId`, `round` **and** `outMonId` all match, and otherwise returns the state unchanged. A disagreeing log folds to a no-op rather than swapping the wrong slot — the same containment `draft/pickUndone` uses. |
| T-03-39 | Tampering | slot-predicate violation in an imported document | accept | `canApply` cannot check it: `DraftState` holds no roster and D-07 declines to materialize eligible ids.
