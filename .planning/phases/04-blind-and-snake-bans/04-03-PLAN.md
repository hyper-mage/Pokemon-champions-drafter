## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 4. Not in `As a … I want to … so that …` form and not
rewritten here — run `/gsd mvp-phase 4` if the three-slot form is wanted.

> Groups run the ban ritual their own way on one shared screen, and nobody sees what they should
> not have seen

**This plan is the second and last shared-substrate plan.** The three action types, the fold they
produce and the D-11 reorder are genuinely shared by both the snake slice and the blind slice, and
splitting them would mean editing `actions.ts`, `reduce.ts` and `model.ts` twice each. It delivers
nothing a player sees; every plan after this one is a vertical slice.

<objective>
Give a ban a vocabulary, a fold and a guard, and move `draft/started` ahead of the pool for the two
modes that need it.

Purpose: the three action-type strings are written into saved documents and read back by later
builds, which makes them "closer to an API than to a label" (`model.ts:57-60`). They are
irreversible once a host saves a tournament. So are the eight `RejectionReason` members
(`reduce.ts:62-64`). This plan names them deliberately, once.

Output: three action types across six sites each, three `DraftState` fields, three `apply` arms,
eight `canApply` arms, the mode-conditional guard relaxation, and four corrected doc-comments.
</objective>

// src/core/actions.ts — the three type strings, pinned
export const BANS_PLACED    = 'bans/placed';
export const BANS_SUBMITTED = 'bans/submitted';
export const BANS_REVEALED  = 'bans/revealed';

export interface BansPlacedPayload {
  type: typeof BANS_PLACED;
  playerId: string;
  monId: string;
  /** 1-based, matching the ban board's `Pass {n}` column headers. */
  pass: number;
}

export interface BansSubmittedPayload {
  type: typeof BANS_SUBMITTED;
  playerId: string;
  monIds: string[];
}

export interface BansRevealedPayload {
  type: typeof BANS_REVEALED;
  bans: { playerId: string; monIds: string[] }[];
}

// src/core/model.ts — the fold
export interface BanPlacement { playerId: string; monId: string; pass: number; seq: number; }
export interface BanSubmission { playerId: string; monIds: string[]; seq: number; }

export interface DraftState {
  // ... every existing field unchanged ...
  /** Snake bans, in log order, from `bans/placed`. `[]` outside snake. */
  banPlacements: BanPlacement[];
  /** Blind submissions, in log order, from `bans/submitted`. `[]` outside blind. */
  banSubmissions: BanSubmission[];
  /** The reveal, from `bans/revealed`. `null` until it lands. */
  bansRevealed: { playerId: string; monIds: string[] }[] | null;
}

// src/core/reduce.ts — the eight new RejectionReason members, pinned
//   banStageNotRunning | notYourBanTurn | alreadySubmitted | wrongBanCount
//   duplicateBanIds | banAlreadyPlaced | bansNotComplete | bansAlreadyRevealed

## Trust Boundaries

| Boundary | Description |
