## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 2. **Note: this Goal line is not written in
`As a … I want to … so that …` form**, and was not rewritten here — see 02-01-PLAN.md.

> A host sets up a real tournament for their group — names, format, pool size, banlist —
> and 4–8 friends draft through it on one shared screen with everything they need visible
> at once.

**Slice delivered by this plan:** a host who ran a draft on the deployed Phase 1 site can
still open it after this phase ships. The document shape widens to hold everything the config
screen will author, and the widening is lossless for every document already in a browser or
sitting in a Downloads folder. End to end: `localStorage` → `persistence.load` → `migrate` →
`adoptTournament` → `fold` → the board renders.

<objective>
Bump `SCHEMA_VERSION` to 2, widen `TournamentConfig` with the six fields the config screen
authors, and migrate — never reject — every Phase 1 document.

Purpose: rejecting a v1 save would need a third import-failure sentence, because both existing
ones (`app.tsx:80-83`) would be false statements about the host's own file. Migration costs one
function and its tests. It also lands the config shape before any UI plan needs it, so no later
plan discovers that a field it authored is silently dropped on import.

Output: a v2 document shape, a real `migrateV1ToV2` step, allow-list entries and bounds for
every new field, and the two config-time seeds materialized into the action payloads.
</objective>
