## Phase Goal

Verbatim from `.planning/ROADMAP.md` §Phase 2. **Note: this Goal line is not written in
`As a … I want to … so that …` form**, and was not rewritten here — see 02-01-PLAN.md.

> A host sets up a real tournament for their group — names, format, pool size, banlist —
> and 4–8 friends draft through it on one shared screen with everything they need visible
> at once.

**Slice delivered by this plan:** anyone at the table can read a Pokémon's typing and base
stats off the pool card, and switch how much of that is shown. It lands on the Phase 1 draft
screen immediately — open the app, look at the pool, change the density, reload, the choice is
still there. End to end: `localStorage` → adapter → `PoolGrid` → `MonCard` → `TypePill` /
`StatBlock`, with the density carried by one attribute.

<objective>
Deliver DRFT-05 and DRFT-06: type pills, base stats, and the three display densities, plus the
two token-system amendments they force.

Purpose: this is the phase's first user-visible change and it is the one that makes the pool
readable from across the room. It also lands `SegmentedControl` — the control shape six
surfaces in this phase reuse — against its first real consumer instead of against a
hypothetical one.

Output: an amended `tokens.css` carrying 18 type hues with measured ratios, `TypePill`,
`StatBlock`, `SegmentedControl`, a density-aware `MonCard`, and the `champions-drafter:view`
adapter.
</objective>

Amendment 1, replacing `:10-11`: density is carried by one attribute, `data-density`, on the
pool pane root, and it redeclares exactly THREE tokens — `--sprite-lg`, `--cell-min`,
`--cell-h`. `--text-label` is deliberately REMOVED from the density-varying set, which is
stricter than Phase 1 rather than looser: it makes it structurally impossible for a density to
shrink text below 14px, and it removes the hazard that a density swap introduces a fifth font
size into a scale this file fixes at four. Density additionally changes the CONTENT of
`MonCard`, which is why the four-token rule had to go: six 14px numbers in a 112px cell are
unreadable at any scale. Because the redeclaration is scoped to the pool pane subtree, the
board pane never inherits it — that is how D-24 ("density affects the pool only") is enforced
structurally rather than by discipline.

Amendment 2, replacing `:80`: colour is reserved for FOUR things, not three. The three semantic
reservations are unchanged (accent, danger, focus ring) and the fourth is the type palette —
eighteen hues, one per Pokémon type, a closed enumerated set derived from roster data. A type
hue may appear on a pool-card type pill and on a type filter control (D-29) and NOWHERE else:
it never marks state, never marks emphasis, never marks a control, and never appears on a board
chip.

Change `--cell-min: 112px` → `128px` and `--cell-h: 144px` → `188px`, and add `--pill-h: 24px`
with the derivation in its comment (14px × 1.4 = 19.6px of text plus 2px above and below).

`--target-min`.

Add the 20 new colour tokens — the 18 `--type-*` hues plus `--type-ink-dark: #0f1216` and
`--type-ink-light: #e8edf2` — with every value and every measured ratio taken verbatim from
