<objective>
Close CR-01 — the keyboard-focus regression plan 02-09 introduced in `SplitPanes.tsx` — and
WR-08, which is its other half. Today a pane state change drops `document.activeElement` to
`<body>` in **both** directions, and the restore control is the only way back from a collapsed
pane, so a keyboard or switch user is dumped to the top of the document and has to tab past
the top bar, the turn banner, the density control, the filter bar and up to 234 pool cells.

Two different causes, one fix each:

- **CR-01 (collapsed → split).** The chrome's ternary renders a bare `<button>` vnode in the
  collapsed branch and a `<>…</>` Fragment in the non-collapsed branch. Preact cannot reuse a
  DOM node across a vnode-type change, so it unmounts and remounts. Fix: one shape in both
  states.
- **WR-08 (split → full width).** The `!isFullWidth` guard removes the very control the host
  just pressed. That is correct as a rule — an expanded pane carries no control of its own,
  because the restore lives on the collapsed strip opposite — so the fix is not to keep the
  node, it is to hand focus to its successor.

Purpose: 02-09 dropped native `disabled` precisely so a keyboard or switch user could reach
and use these controls. A control that throws that user to `<body>` when they use it defeats
the reason it was built. This is the phase's own regression, on the files this phase shipped.
Output: one chrome shape, one focus handoff, three regression tests, and a `side()` signature
in which an unavailable expand without a reason is unrepresentable.

**MVP slice.** One user-visible behaviour restored end to end — *operate the pane controls by
keyboard without losing your place* — plus the tests that pin it. It is deliberately not
inflated into layers it does not have. On the ROADMAP `Mode: mvp` tag versus a `Goal` line
that is not in user-story form: that mismatch is recorded in `02-01-PLAN.md` and in
`02-VERIFICATION.md`, is flagged for a human (`/gsd mvp-phase 2`, or drop the tag), and is not
this plan's to resolve. No user story is invented here, following the same precedent.

**On the `requirements:` claim.** `DRFT-10` is claimed as a re-touch, not as new coverage — it
is already SATISFIED and was claimed by 02-06, 02-09 and 02-10 for this same surface. The link
is real rather than bookkeeping: D-21 makes expanding the board the only way pick-history
chips show their names, so a keyboard user who cannot operate the expand/restore pair loses
the named view of the pick history that DRFT-10 is about.
</objective>

    ## src/ui/components/SplitPanes.tsx — part 2, the focus handoff

    Import `useLayoutEffect` and `useRef` from `preact/hooks`. Both are part of `preact`; this
    is not a new dependency. (If `useLayoutEffect` turns out not to flush under `preact/test-utils`
    `act` in this repo's happy-dom setup, `useEffect` is the acceptable fallback — record the
    swap and its reason in the summary rather than leaving the tests red.)

    In the component body, not inside `side()` (hooks must not be called from a function that
    runs twice per render):

    - `collapsedControlRef` — a `useRef<HTMLButtonElement | null>(null)`. Attach it in `side()`
      as `ref={collapsed ? collapsedControlRef : undefined}`. Conditional on purpose: both panes
      call `side()`, only one can be collapsed at a time, and an unconditional attach would let
      the second call overwrite the first.
    - `activatedControlRef` — a `useRef<HTMLButtonElement | null>(null)`. In the click handler,
      on the two paths that actually call `change` (never on the refused path), read
      `const button = event.currentTarget as HTMLButtonElement;` and set
      `activatedControlRef.current = document.activeElement === button ? button : null;`
      **before** calling `change`. The `activeElement` test is what stops this from stealing
      focus: it only arms the handoff for a host who was actually on the control.
    - A `useLayoutEffect` with **no dependency array**, so it runs after every render and always
      clears its own state. It reads `activatedControlRef.current`, immediately sets that ref
      back to `null`, returns if it was `null`, returns if the recorded element is still
      `isConnected` — that is the collapsed→split case, where Preact reused the node and focus
      never left it — and otherwise calls `collapsedControlRef.current?.focus()`.

    Why `isConnected` rather than keying the effect on `pane` and guessing the direction: the
    effect then states its own precondition ("the control the host was on has left the
    document") instead of encoding a mapping from pane transitions to outcomes that a later
    change to the membership rule would silently invalidate.
