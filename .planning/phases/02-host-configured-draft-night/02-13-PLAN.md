  <what-built>
    Plan 02-11 fixed a keyboard-focus regression that plan 02-09 introduced. Operating either
    pane control used to throw focus to the top of the document: the chrome rendered a different
    element shape in the collapsed and split states, so the browser destroyed and recreated the
    button instead of reusing it, and expanding a pane removed the very button the host had just
    pressed. Now there is one control in one shape, relabelled rather than replaced, and when a
    pane expands — which genuinely does remove that pane's control — focus is handed to the
    restore control on the collapsed strip opposite. Nothing about which states are available
    changed: the pool still cannot be expanded mid-draft.

    Plan 02-12 changed three things a person can see. The inert `Expand the pool` no longer
    lights up on hover, so it stops looking pressable while also showing a "not allowed" cursor.
    The chrome row can now wrap, so when the button and its reason cannot share a row the reason
    drops below instead of the button sliding off the left edge where nothing can scroll it back.
    And the em dash before the reason moved out of the stylesheet into the markup, hidden from
    screen readers, so the whole line the host reads is now covered by a test — it should look
    exactly the same as before.

    `.pane__chrome`'s reserved height is unchanged. The alignment the host approved under plan
    02-10 should be identical, and check 3 exists to prove it.
  </what-built>

  <how-to-verify>
    Run `npm run dev` and open the printed URL.

    **Setup.** Start a new tournament with two players and any valid pool, `Start draft`, and make
    one pick so the board is not empty.

    1. **Keyboard, expanding.** Press Tab until the focus ring is on `Expand the draft board`.
       Press Enter. The board takes the full width and the pool collapses to a narrow vertical
       strip. **The focus ring must now be on the `Show the pool` button on that strip.** It must
       not have vanished, and pressing Tab once from there must not start you at the top bar. This
       is the failure being fixed: focus used to land nowhere at all.

    2. **Keyboard, restoring.** With the focus ring still on `Show the pool`, press Enter. The
       panes return to side by side. **The focus ring must still be on that same button**, which
       now reads `Expand the pool` and is dimmed. It should not jump, disappear, or reappear
       somewhere else on the screen.

    3. **The panes still line up.** Compare the top edge of the pool grid with the top edge of the
       draft board. They must start on the same line — the same thing you confirmed at step 2 of
       plan 02-10. Expand the board and restore it once more, and confirm they still line up
       afterwards. This is a regression check: if anything here looks different from what you
       approved before, say so, because nothing in this round was supposed to move it.

    4. **Hover, with its control case.** Mid-draft, hover the mouse over `Expand the pool`. Its
       background must **not** change, and the cursor shows "not allowed". Now hover over
       `Expand the draft board`. Its background **must** change. Both halves matter: if neither
       reacts, the fix has gone too far and taken the live control's hover with it.

    5. **The reason line.** Beside `Expand the pool` read the text exactly. It must be
       `— Available once the draft is complete` — one em dash, one space, then the sentence, all
       on the same row as the button, in the same muted grey as before. Two dashes, a missing
       dash, or a dash on its own line are all failures.

    6. **Narrow the window.** Drag the browser window narrower — or zoom in with Ctrl/Cmd-`+` —
       until the button and its reason can no longer fit on one row. **The reason must drop to a
       second row underneath, and the whole `Expand the pool` button must stay visible and
       clickable.** No part of the button may be cut off at the left edge, and the page must not
       grow a horizontal scrollbar. Then widen it back and confirm the row returns to one line.

    Steps 1 and 2 are the ones this round exists for. Step 3 is the regression guard, and step 4's
    second half is the control case — a check with no control case cannot tell a fix from a
    breakage.
  </how-to-verify>
