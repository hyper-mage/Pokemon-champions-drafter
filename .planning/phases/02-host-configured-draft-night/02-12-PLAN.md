    ## WR-01 — the hover rule excludes the inert state

    Change the selector `.pane__button:hover` to `.pane__button:hover:not([aria-disabled='true'])`.
    The declaration itself, `background: var(--color-surface-raised);`, does not change.

    The state here is `aria-disabled`, not native `disabled`, so the exclusion has to name the
    attribute — `:not(:disabled)` would match nothing, because 02-09 deliberately dropped the
    native attribute so the control stays focusable. Today the inert control gets the same hover
    response as the live one while `cursor: not-allowed` applies at the same time, so the host
    gets one signal saying pressable and one saying not-pressable on the same element, followed
    by a click that does nothing. Comment the exclusion with that one-line reason and cite the
    three in-repo precedents by file and line.

    ## WR-05 — the chrome row wraps rather than overflowing where nothing can reach it

    Add `flex-wrap: wrap;` to `.pane__chrome`. Keep `flex: none`, `justify-content: flex-end`,
    `align-items: center`, `gap: var(--space-2)` and `min-height: var(--target-min)` exactly as
    they are.

    Why it matters and why it is safe: the row holds a button and a ~38-character label, neither
    of which shrinks below its content, and a `flex-end` row that does not fit overflows its
    **start** edge — which is not reachable by scrolling in any browser. The button, not the
    label, is what goes off the side. At every width where the row fits, `wrap` changes nothing;
    it only changes what happens in the case that is currently broken. `min-height` stays a
    floor, so the chrome is still exactly one target tall whenever the row fits and grows only
    when the alternative is losing the control. Cite `FeasibilityBar.css:14` as the precedent for
    the identical structure.

    Do NOT take the alternative of truncating `.pane__reason` with an ellipsis. Truncating the
    explanation is the worse of the two options — the explanation is the entire reason 02-09
    renders this control at all.

    down what you actually found and stop rather than writing a comment you cannot support.**

      Rendering the button is what fixed UAT test 9; the misalignment was a symptom of the
      omission rather than a separate defect.
    - What the chrome's own `min-height` does is reserve the row so an expanded pane's empty

    - Correct the `align-items: center` attribution too. It does not prevent wrapping — and with
