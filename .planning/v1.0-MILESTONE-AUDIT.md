**1. REQUIREMENTS.md checkboxes** read 73/94 while its own traceability table read 92/94 Complete. Already flagged inside `03-VERIFICATION.md:182-188`.
**Fixed** — 19 verified requirements ticked (`DRFT-01/02/03`, `DRFT-05…16`, `RULE-07`, `BAN-01`, `BAN-02`, `BAN-08`). `BAN-07` and `EXPO-04` deliberately left unticked to match their Partial/Pending status. Checkboxes and table now agree at 92/94.

**2. 23 REQ-IDs missing from SUMMARY frontmatter** — *root cause corrected; this was mischaracterised on first pass.*

This is not per-file drift and nothing was backfilled. The SUMMARY template changed across phases:

| Frontmatter shape | Summaries |
|---|---|
| `requirements-completed:` | most of Phase 1 |
| `requirements:` | `01-10`, `05-01`, and a few others |
| `provides:` / `affects:` dependency graph, **no requirement-ID key at all** | 22 of 62, incl. all of `03-07…03-12`, `04-01…04-04`, `05-09`, `05-12` |

`gsd-sdk query summary-extract --fields requirements_completed` reads only the `requirements-completed` spelling, so those 22 summaries return empty by construction — the tool and the template disagree, and the phases that adopted the richer dependency-graph format simply stopped recording requirement IDs there.

No data was lost. The authoritative per-requirement mapping lives in each phase's VERIFICATION.md requirements table (`Requirement | Source Plan | Description | Status | Evidence`), which is complete for all 94 and is what this audit's coverage figures were computed from. Backfilling 22 historical summaries would mean writing frontmatter their own template never had, reconstructed after the fact — a worse record than the accurate one that already exists. Left as-is deliberately.

**3. Both quick tasks report `[missing]`** to `gsd-sdk query audit-open` — *diagnosis corrected; this is an upstream SDK bug, not a repo issue.*

`scanQuickTasks` reads an unprefixed filename:

```js
// sdk/dist/query/audit-open.js:78
const summaryPath = join(taskDir, 'SUMMARY.md');
```

The GSD quick workflow writes a prefixed one:

```
// get-shit-done/workflows/quick.md:757
- Create summary at: ${QUICK_DIR}/${quick_id}-SUMMARY.md
```

The two never match, so `audit-open` reports **every** quick task `[missing]` regardless of its contents. Proof: `260820-l4u` has carried `status: complete` in its frontmatter since 2026-08-20 and still reports `[missing]`.

Both quick tasks are complete. `260813-tep` shipped in `cb380bc`, `364e2dd`, `d34cc2a` and already carried `requirements-completed: [PERS-03, WR-07, T-02-15]` and `completed: 2026-08-14`; `status: complete` was added for consistency with its sibling, but it does not change the audit output and nothing in this repo can. Nothing to fix here.

**4. STATE.md frontmatter** read `completed_phases: 4` / `percent: 80`, and its Current Position still read `Plan: Not started` pointing at `/gsd-plan-phase 5` with a `47/47 plans (4 of 5 phases complete)` progress bar.
**Fixed** — frontmatter now `completed_phases: 5` / `percent: 100`; Current Position rewritten to reflect the audited milestone; the 2026-08-20 sequencing note marked resolved (execution held the 1→5 order and Phase 5 shipped with `REFR-01…03` intact, so the committed snapshot never went stale without an in-app path off it).
